# F6.7 Council Portal

## Status: **Selected – Client Approved (chat approval 2026-11-12)**

Optional Section 11 Council Portal add-on. Core HMore still has **exactly six roles**. Council officers are an **add-on identity** stored in `council_portal_officers` (`addon_role_label=council_officer`) and are **never** added to `HMoreRole` / `organisation_memberships.role`.

## Delivered

- Org Admin / Super Admin manage officers and application shares (`council_portal.manage`)
- Secure sharing of housing applications with scoped fields
- Optional approval history and evidence **metadata** (no raw file bytes by default)
- Officer inbox + application detail + shared-status report summary
- Access logs + audit events
- Web admin/officer UI at `/dashboard/council-portal`

## Explicit isolation rules

- No seventh value in `HMoreRole`
- `test_exactly_six_approved_roles` remains green
- Tenant caseload / private notes never exposed
- Only applications with an active `council_portal_shares` row are visible to officers
- Draft applications cannot be shared

## API

Prefix: `/api/v1/council-portal`

Admin (org context + `council_portal.manage`):

- `GET /admin/dashboard`
- `GET|POST /admin/officers`, `PATCH /admin/officers/{id}/status`
- `GET|POST /admin/shares`, `POST /admin/shares/{id}/revoke`

Officer (authenticated user + active officer row + `X-Organisation-Id`):

- `GET /officer/inbox`
- `GET /officer/shares/{share_id}`
- `GET /officer/reports/summary`
