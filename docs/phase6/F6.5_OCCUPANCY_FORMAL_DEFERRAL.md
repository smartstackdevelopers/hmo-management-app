# F6.5 Room Occupancy — Formal Written Deferral (Live Camera / Counting)

**Status:** **FORMALLY DEFERRED** for live camera/sensor counting  
**Date:** 2026-11-12  
**Plan reference:** HMore Proposal-Exact Complete Implementation Plan v1.0 — Phase 6 exit (occupancy under DPIA Go **or** formally deferred with written gate)

## Decision

Live people-counting (camera/RTSP/sensor ingest that updates estimated occupancy) remains **disabled** until each organisation completes the privacy gate:

| Gate field | Default | Required for live counting |
|------------|---------|----------------------------|
| Feasibility assessment | `not_started` | Approved / complete per product rules |
| DPIA | `not_started` | Approved |
| Signage | `not_started` | Complete |
| Retention policy | `not_started` | Approved |
| Camera compatibility | `not_started` | Confirmed |
| `live_counting_enabled` | `false` | Explicitly enabled after gate |

HMore **never** auto-approves DPIA. Until the gate is complete, `POST /api/v1/room-occupancy/counts/ingest` returns **403**.

## What is delivered now

- Room occupancy module, models, migration `20261111_4300_f65`
- Dashboard, alerts, history/usage APIs, manual corrections with audit
- Five occupancy statuses; offline rooms expose `estimated_count: null` (not fake zeros)
- Celery sweep for stale/offline + retention
- Web + Expo staff surfaces for permitted users
- No facial recognition, no identity tracking, no raw video storage by default

## What is deferred

- Production live camera/RTSP streams
- Edge ingest of live counts without org-completed DPIA/feasibility/signage/retention
- Claiming “live estimated people counting” as operationally live for any org that has not completed the gate

## Re-enablement

Live counting may be enabled **per organisation** only after authorised staff record gate approvals in HMore and set `live_counting_enabled`. Until then this written deferral satisfies the Phase 6 exit alternative for occupancy.
